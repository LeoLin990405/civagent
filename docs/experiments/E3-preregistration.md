# E3 preregistration — does the topology effect replicate across model families?

Registered 2026-08-03, before any E3 `--execute` invocation, and before the
first non-doubao cell is run.

## Why this supersedes E2

E2 fixed the backend at `cn:doubao` for every arm, on the reasoning that a
paired comparison must not vary the model. That reasoning is correct and the
conclusion drawn from it was too narrow: it forbade *varying the model within a
pair*, not *running the whole paired set on more than one model*.

Treating the backend as a **blocking factor** keeps the pairing clean and adds
what E2 could not produce:

- Inside a backend, a regime and its scrambled control run on the same model, so
  a score gap cannot be a model effect. Identical to E2's guarantee.
- Across backends, the same 15 cells are repeated independently, so the question
  becomes *does the effect reappear on a different model family* rather than
  *what happened on doubao*.

That distinction is not cosmetic for this project. The proposition in README
§1.2 is that historical topologies are **reusable orchestration patterns**. An
effect visible only on one model is not a reusable pattern; it is a property of
that model. E2 could not tell those apart. E3 can.

A practical consequence, stated so it is not mistaken for the motive: the five
providers hold five independent quotas, so the run parallelises and is no longer
bound by one account's rate window. The E2 run stalled for 84 minutes on a
self-imposed AFP throttle. That is a real benefit and it is not the reason for
the redesign — the replication question is.

## What carries over unchanged

- The five source/control pairs, controls generated by `engine/baseline.mjs`
  with decimal seed 42, persona held constant and only the wiring rewired.
- The three scenarios: `plague-response-01`, `regional-militarization-01`,
  `border-city-autonomy-01`.
- `--no-skill` on every arm, `--enforce-dispatch` on every arm, anonymized and
  order-swapped judging, actor-stratified transcript selection.
- The pre-enforcement dispatch plan as B's dependent variable, and its
  comparison against the declared topology (`planDiff`).

## The blocking factor

Five backends, each verified live by an actual request before registration
(each returned a reply, not merely a launcher-present check):

| Backend | Model |
|---|---|
| `cn:doubao` | doubao-seed-evolving |
| `cn:glm` | glm-5.2 |
| `cn:minimax` | MiniMax-M3 |
| `cn:mimo` | mimo-v2.5-pro |
| `cn:qwen` | qwen3.8-max-preview |

`cn:kimi` and `cn:stepfun` are excluded. Kimi's credentials return 401; a
launcher that exists is not a backend that answers. Excluding them is registered
here rather than decided after seeing results.

Design: 5 backends × 3 scenarios × 5 repeats = **75 ten-arm tournaments, 750
arms**. The four doubao cells already completed under E2's identical
configuration are retained as part of the doubao stratum; the remaining eleven
doubao cells and all cells for the other four backends are new.

## Falsifiable predictions

- **D1 (primary).** Within each backend, scored over resolved pairs only, the
  historical wiring wins a clear majority. **The effect must appear in at least
  four of the five backends to count as replicated.** If it appears in one or
  two, the honest reading is that it is a property of those models, not of the
  topology, and that must be reported as plainly as a positive result.
- **D2.** Pairs whose gap does not exceed that backend's own judge position
  effect (`biasReport.positionEffect.maxAbsDelta` — the worst judge's movement,
  not the mean) are **unresolved**, never a win or a loss. D1 is scored over
  resolved pairs and the unresolved count is reported per backend.
- **D3.** An arm that fails `enforcement_passed` or is not
  `participation_observed` is excluded from D1 and reported separately. An arm
  that did not exercise a topology has not tested one.
- **D4 (B side).** The pre-enforcement plan's deviation from the declared
  topology is reported per backend. If deviation differs sharply across models,
  then "is this wiring adopted" is model-dependent, which bears on the reusable-
  pattern claim independently of D1.

## What E3 cannot answer

- **Absolute scores are not comparable across backends.** The five models differ
  in capability and verbosity; only the direction of the within-backend paired
  contrast may be read across strata. Any table that ranks backends against each
  other is a misreading of this design.
- **One seeded rewiring per regime.** A result either way is about seed 42's
  intervention on these five regimes, not about random graphs in general.
- **Enforcement proves roster invocation, not typed edges.** The coordinator
  called the offices the topology names; whether any `command` / `review` /
  `info` / `veto` edge executed remains unobservable (README §9.6).
- **The plan question is itself an intervention.** Asking which offices the
  coordinator would call raises the salience of delegation, so D4 measures
  stated intent when asked, not spontaneous behaviour. Carried over from E2's
  registration and unchanged.
- **n = 5 per cell** at a noise floor that reached 1.67 in calibration. Gaps
  under roughly 2 points will mostly land in D2's unresolved bucket, and that is
  the intended behaviour rather than a shortfall.
